Operator OS is an open-source AI operating system for people who run a business. It is built so your spend is proven, every lead is answered, your numbers hold up, your compliance is defensible, and nothing fails quietly.

It installs as a Claude Code plugin: AI agents, skills and enforcement hooks for operators running growth marketing and GTM, with a vault that remembers. Use it for GTM automation that stays inside your rules: paid media staged for your approval, lead follow-up that passes a review seat, and reporting whose numbers are recomputed before they count.

What you get

Spend proven

Every dollar is tied to a number you can recompute, and no agent can move your money on its own.

  • A rate and cost governor in front of every vendor call
  • A write gate: the agent stages a change to an ad platform, you apply it
  • A rule that research, report and a senior tie-out must agree before a number counts
  • A paid-media seat that stages every change and never pushes one

Every lead answered

Contact with customers is designed, reviewed and registered before it ships, so a lead is never lost to a loose end.

  • A review seat that must pass any new automated customer contact
  • A consent-evidence rule: nothing reads as tampered unless it was
  • A rule that new lead sources enter through one registered door
  • Sensitive records handed only to a model on your own machine

Numbers trusted

One definition per number, a counting basis printed beside it, and a different seat checking the work.

  • The accuracy hierarchy: prove the inputs, compute, then tie out from a different pull
  • A gate against hand-summed figures in a terminal
  • A docs-drift check that tests a document's claims against the code
  • A vault where every count carries how it was counted

Compliance defensible

Data is classified before it is touched, every action leaves a record, and a gap assessment is a skill, not a project.

  • Four data tiers and a routing table for which tool may see which tier
  • A compliance audit skill that maps controls to the frameworks that apply
  • A local-only zone the cloud session cannot read
  • An audit trail of every tool call and a secret scrubber for transcripts

Nothing failing quietly

A job that can fail without telling you is treated as unfinished. Every failure path ends in an error, a visible refusal or an alert.

  • A write-time hook that refuses swallowed errors and hidden exit codes
  • A rule that every wait has a deadline and every long task states a budget
  • A hook that refuses detached processes nobody supervises
  • A rule that a lookup which finds nothing says so, instead of returning empty

Start here

  1. Install the plugin
    One command. It adds the agents, skills, hooks and system packs. Open a project and one status line says which optional parts are configured.
  2. Install the rules
    Ask for the install-rules skill so the doctrine lives in your project.
  3. Make your vault
    Copy the starter vault, or run the init-vault skill, and set the vault variable.
  4. Read the example
    Open the fictional company's vault and follow one rule from its raw source to its card.
  5. Run the loop
    Build with one seat, check with another, and stop after three rounds.
  6. Add your own hook
    Block a mistake only you know about, and prove it with a test.
  7. Give it a goal
    Run the goal skill with a plain outcome and watch the gates hold.

The operating doctrine in brief

Loud failure

Anything that can break ends in an error, a visible refusal or an alert row. A silent success is a bug.

Review loop

One seat builds, a different seat checks, the check is bounded, and a halt is a valid ending.

Leak gate

Nothing sensitive leaves on a prose rule alone: a local-only wall, an egress watch, a secret scan, a path-disclosure block.

Name the thing

You never receive a ticket number. Every reference says what the thing is, in plain English.

Execute now

If it can be done now, it is done now. The only reason to stop is a blocker that sits on you.
