Case studies (7)

Seven spec kits, rewritten around an invented company so you can see how the harness's own rules were produced and what a good kit looks like.

The company is fictional: Harbor and Pine Home Services, forty employees, two metro areas, a small call center, a CRM, three ad platforms and an owner who runs the business with AI agents. How to read a kit: start with the problem paragraph, skim the stories, then read the requirements and the success criteria. Every story has an independent test and every failure path has a named end.

Harness Autonomy Hardening

The rule it produced: One approval per goal, keyed on the tool's invocation, not on words in a command.

Harbor & Pine's harness had every piece of autonomy (hooks, gates, receipts, specialist agents, a status board) but each piece was built for one moment: one approval per write, one check per command. Run end to end toward a goal...

Vault Human Naming: every note named for a person, not a database

The rule it produced: Rename for a human, with a checkpoint, aliases, rewritten links and an automatic rollback gate.

About 1,700 vault notes carried machine names: card_unified-reporting-platform-117, learning_a_default_value_holds_two_populations_so_no_rate_over_it_means_anything. Type prefixes, snake_case, kit-number suffixes. The filename is the owner's primary interface in the vault and in the notes app, and it read like clutter.
