Agents (26)

Specialist seats, each pinned to a model tier and an effort level. Builders run on cheaper tiers; the seats that check run on the strongest tier, read-only, and send defects back down.

Every agent below is listed with its model tier, effort and whether it can edit files, straight from the agent's own definition.

Full description

UI/UX engineer seat. Owns how a product works before anyone builds it - information architecture, user flows, every screen state (loading, empty, partial, error, success), low-fidelity wireframes, interaction and accessibility specs, and the front-end handoff package that maps each screen to components, data sources and acceptance criteria. Runs BEFORE front-end implementation and accepts the built screens after. Use for "plan the flows", "wireframe this", "what states does this screen need", "write the handoff", "audit this UI", or any feature where front-end tasks would otherwise start without a design. Works with web-designer (visual layer) and hands off to implementer (front end). Delegate with [task_type=ui_ux_design]. Evaluated by the handoff completeness check (zero return questions from the implementer), axe-core violations on built screens (target 0), and web-designer's cross-review.

Full description

Adversarially gates every corpus-pruner proposal before anything leaves the corpus. Read-only. Verdicts are PASS / PASS-WITH-CONDITIONS / BLOCK per row, and it never edits the proposal. corpus-pruner

sonneteffort: mediumread-only

Full description

Finds corpus rows that should not be in the knowledge corpus and proposes what to do with them, one named class at a time, with the evidence attached. Never deletes, never edits a note, never touches the vault. Works from a candidate queue file (`.operator/prune/candidates.jsonl`) written by a deterministic scan of your own, not on a schedule. Its output is a proposal file that corpus-pruner-sr adversarially gates before anything is archived. Delegate with [task_type=content_research].
