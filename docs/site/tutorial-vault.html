Set up the starter vault

The vault is plain markdown that the assistant reads at the start of every session. By the end you have one, with a first rule captured from something you corrected, and you have found it again by search.

Step 1. Create it

The starter vault, the example vault and the search and lint scripts live in the repository, not in your project, so start by cloning it. Keep it anywhere; you only need it for this tutorial.

git clone https://github.com/ndnstyl/GTM-growth
cd GTM-growth

Then either copy the full starter (all folders and templates) or let the plugin make a minimal one.

cp -R starter-vault ~/operator-vault
export OPERATOR_VAULT=~/operator-vault

Or, inside a session, /operator-os:init-vault, then run export OPERATOR_VAULT=<the path init-vault printed> in the shell you will use for steps 2 and 4, because the lint and search commands read that variable. Add the export line to your shell profile so it sticks.

What you should see

With init-vault you get four lines beginning created: (MEMORY.md, log.md, _WIKI-SCHEMA.md, a learning template) and init-vault: vault ready at .... With the copy, ls ~/operator-vault shows 00-BOARD, 10-PROJECTS, 20-AREAS, 30-KNOWLEDGE, 40-SOPS, 90-ARCHIVE, raw, templates and the index MEMORY.md.

Step 2. Check it is healthy

python3 plugins/operator-os/scripts/memory/vault-lint.py
What you should see

A short report ending in zeros for links into 90-ARCHIVE and ambiguous archive links, and Read-only run; nothing was modified. (A line for stub notes appears only once the vault holds notes.) Lint only reads. It never rewrites a note.

Step 3. Capture a rule from a real correction

The next time you correct the assistant, say so in a sentence, then run:

/operator-os:distill

Open Claude Code in your own project (it finds the vault through OPERATOR_VAULT, wherever you are) and try a made-up correction: "When you report weekly spend, always say how it was counted." The skill writes the exact words into raw/, writes one note whose title is a sentence, and files a hook line for it in the folder's map.

What you should see

A new file in raw/ with your words, one new note in 30-KNOWLEDGE/ that cites it as [[raw/...]], and a hook line for it in the folder's _map.md. A line in MEMORY.md appears only when the rule must load before any search runs.

Step 4. Find it again

Back in the GTM-growth folder:

python3 plugins/operator-os/scripts/memory/vault-search.py "weekly spend counted" --snippets
What you should see

A ranked list with the new note first and a short snippet under each result. A search that finds nothing prints 0 results (honest no-hit, try different terms or grep), never an empty page. That sentence is deliberate: silence would read as proof of absence.

Step 5. Read a vault that has been used

The example vault is a fictional home-services company. From the GTM-growth folder, point at it and search:

OPERATOR_VAULT=examples/example-vault python3 plugins/operator-os/scripts/memory/vault-search.py "weekly cap spend" --snippets
What you should see

The rule Ad Spend Over the Weekly Cap Needs the Owner's Yes first, then the raw excerpt it came from, then the campaign card that cites it, with the related pause rule further down. That chain, source to rule to consequence, is the whole method.
